# new-titles — project memory

Library new-acquisitions discovery for a scholarly community. Launch target for `nt-map`: **2026-05-15**.

## What this is

A monorepo producing three deliverables from a shared data pipeline:

- **nt-map** — public interactive map of recent acquisitions (5/15 launch)
- **nt-website** — monthly standalone HTML fragment, ingested by work's CMS (post-launch)
- **nt-recommend** — per-scholar geo-based recs (post-launch)

Fed by:

- **nt-data** — Zod schemas, Pleiades gazetteer, ingest from librarian CSV/JSON exports
- **nt-classify** — scikit-learn classifier that tags each record with one of 6 regions of interest

## Data pipeline (one direction only)

```
librarian CSV/JSON → nt-data ingest → acquisitions.json → nt-classify → classifications.json
                                                                        ↓
                                         nt-map / nt-website / nt-recommend
```

Raw librarian shelflist exports land in `packages/nt-data/data/exports/` **locally only** — that directory is gitignored. The ingest script transforms them into a Zod-validated `acquisitions.json`, which *is* committed (that's the derivative the apps consume). Nothing mutates records after ingest — enrichment (classifications, place resolution) sits beside them in separate files keyed by record id.

## Geographic convention

- **"Geographic" means subject/setting of the work**, not publication place or author origin.
- Pleiades IDs are already in MARC $0 in many records. Those are authoritative.
- Post-launch: Getty TGN fallback, then subject-heading inference for unresolved records.
- `packages/nt-data/data/gazetteers/pleiades.json` is a vendored subset — only entries we reference. Regenerated by `scripts/refresh-gazetteer.ts` when new IDs appear.

## Conventions

- **TypeScript everywhere except nt-classify** (Python 3.12 + sklearn). Python stays scoped to one package.
- **Zod is the single source of truth** for record shapes. Import types from `@nt/data`; don't redeclare.
- **Derivatives are committed; raw shelflists are not.** `acquisitions.json`, Pleiades gazetteer subset, and (post-launch) classification outputs live in git. Librarian shelflist exports stay local — gitignored under `packages/nt-data/data/exports/`. The librarian's system is the source of truth for the raw data.
- **No backend at launch.** All deliverables are static. When per-scholar personalization arrives, reassess.
- **Trunk-based.** Short-lived branches, PRs with CI gates, main always shippable.

## 5/15 scope guardrail

Only `nt-data` + `nt-map` ship. Other packages are scaffold-only. If something feels like scope creep toward 5/15, push back — it almost certainly is.

Post-launch order: nt-classify → nt-website (port existing work) → nt-recommend.

## CI gates (all required to merge)

- `pnpm typecheck` — strict TS across all packages
- `pnpm lint` — Biome
- `pnpm validate` — Zod parse every record in acquisitions.json
- `pnpm build` — every package builds
- `ruff check` + `pytest` — when Python files exist in nt-classify

## Hosting

- `nt-map` → GitHub Pages (prod). Preview builds uploaded as GH Actions artifacts on PRs.
- `nt-website` → HTML artifact downloaded and pasted into CMS.
- Base path for nt-map reads `VITE_BASE_PATH` so it ports to any repo/domain.

## Claude skills

Recurring workflows live in `.claude/skills/`. Invoke with `/<skill-name>`:

- `/ingest` — ingest a new librarian export, validate, open PR
- `/classify` — run classifier on new records, update classifications.json (post-launch)
- `/build-monthly` — generate a month's HTML digest (post-launch)
- `/add-place` — manually add a place to the gazetteer
- `/bump-deps` — monthly grouped dependency refresh

When in doubt about the right workflow for a recurring task, codify it as a skill rather than doing it ad hoc.
